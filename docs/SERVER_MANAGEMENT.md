# サーバー管理

この Mac で動く baby-media-web（iOS「凛紬花ちゃん」の共有サーバー）と MyMusic LAN Cardinal を読み取り専用で確認する。MyToolBox の「ネットワーク・サーバー」→「サーバー管理」を開くと1回取得し、「状態を更新」で再取得する。詳細画面は自動ポーリング・履歴保存をしない。更新中の値は前回の結果で、行ごとに最終確認日時を表示する。

## 確認対象

- 写真サーバー：固定の `http://127.0.0.1:8080/health` が HTTP 200 を返すか。curl はユーザー設定・プロキシ・リダイレクトを使わず、本文を破棄する。最大3秒。
- 音楽サーバー：TCP 8768 の Python 待受を確認。別プロセスなら要確認、欠損は取得不可。8769 は同じ音楽サーバーの内部用ポートのため別サーバー扱いしない。音楽の認証情報・カタログ・設定APIにはアクセスしない。待受確認はアプリの同一性や再生成功を保証しない。
- launchd：`launchctl blame system/com.baby-media-web` の実行理由応答を参考情報として表示。OS の診断用コマンドであり、状態の安定したAPIではない。空応答・実行失敗は取得不可。環境変数を含む `launchctl print` は取得しない。
- TCP 8080：lsof の待受 PID と node／別プロセスを表示。引数や接続先一覧は取得しない。launchd との PID 一致やアプリの識別までは保証しない。
- Tailscale：App Store 版の固定 CLI を専用 CLI モードで照会。自端末の接続状態・オンライン状態のみ表示し、他端末一覧を要求しない。
- Serve：HTTPS 443 のルートが `http://127.0.0.1:8080` を転送する設定か、Funnel が有効な設定があるかを表示。ホスト名・tailnet名・アドレスは表示しない。

## 制約と安全

専用 actor で直列取得し、UI をブロックしない。各子コマンドは最大5秒で終了させるため全8項目で最大約40秒。失敗・権限不足・未導入・解釈不能は取得不可。HTTP 非200や期待と異なる VPN 設定は要確認とし、接続失敗をサービス停止と断定しない。コマンドの生出力・stderr は表示しない。既存の制限付きコマンド実行器を再利用し、Tailscale 用の固定環境変数だけを追加する。

写真・動画・認証情報・全環境変数・サービスログは取得しない。VPN変更、外部公開、権限変更、起動停止、常駐登録、認証操作の機能はない。Mac 全体の負荷は既存システムモニターで確認する。別 Mac や外出先からの接続、VPN 経由の実到達性、ログイン・画像閲覧はこの画面の確認対象に含めない。

## 実装と検証

`ServerManagementCollector` → `ServerManagementModel` → `ServerManagementView`。項目の解釈・欠損・非200・接続失敗・Funnel・ポート不一致・表示内容の秘匿は `ServerManagementTests` で検証する。起動・手動更新の実機操作は別途確認する。[標準検証](../TESTING.md)に従う。

## メニューバーの状態表示
本体だけが「サーバーアイコン＋上段：写真マーク・状態点／下段：音楽マーク・状態点」を表示し、起動時・60秒ごと・wake時・手動時に写真のhealthと音楽8768待受の2項目だけを確認する。独立helperは常駐監視を開始しない。専用actorと重複防止で取得を直列化する。
緑は写真のHTTP 200／音楽のPython待受、橙は要確認、灰は未取得・取得不可・150秒超の期限切れ。復帰時は結果を破棄して再確認する。点はサービス停止や外部到達性を断定しない。メニューには文字による状態・確認時刻・確認内容・手動更新・既存詳細画面への入口を表示する。履歴保存・通知・サーバー操作はしない。
`tools/VerifyServerMenu.swift` は実ServerStatusImageの正常／要確認／古い／未取得を明暗両方で非表示描画し、実コレクターの2項目を照会する。2026-10-21に専用更新処理で本番反映。詳細画面の取得・手動更新を確認済み。メニューバーの2段表示・実クリックと、物理キーによる配置／復元も利用者確認済み。

## 写真・音楽カード
画面の先頭で写真／音楽を別カードに分け、アプリ名・HTTP応答／待受状態・ポート・確認内容・最終確認日時を表示する。横幅680pt以上で2列、狭い画面では縦に並べる。写真のHTTP 200は「応答あり」、音楽のPython待受は「待受あり」とし、取得不可・未確認は灰色、要確認は橙で示す。
写真の8080待受・launchd・Tailscale・Serveは「写真サーバーの詳しい診断」にまとめ、初期状態では折りたたむ。音楽に写真用VPNの結果を混ぜない。更新中は前回結果であることを表示する。取得方法やメニューバーの周期は変更しない。
`tools/RenderServerManagement.swift`で実Viewの4テーマ×正常／診断展開／取得不可／未確認／更新中×幅440／800の40画面を非表示描画する。合成データを使用し、表示時の実取得は無効化して本番状態へ触れない。2026-10-21に専用更新処理で本番反映。写真／音楽の実表示・手動更新・診断の開閉・スクロールを確認済み。

## 音楽の詳しい診断（開発版）
写真とは独立した折りたたみ欄に、配信用TCP 8768／常駐サービス／内部TCP 8769を表示する。常駐確認は現在ユーザーの`gui/<uid>/local.mymusic.cardinal-server`へ`launchctl blame`を実行し、実行理由に応答があるかだけを確認する。空応答・失敗は取得不可。PID一致や安定したサービス状態APIとは扱わない。
内部8769はlsofでPythonとloopback（127.0.0.1／::1）の待受を確認する。想定外プロセスやloopback以外の待受は要確認、欠損は取得不可。設定ページのHTML・API・認証情報・音楽カタログ・音源・ログは取得しない。8768と8769のPID一致や再生成功は未確認。メニューバーは従来の写真healthと音楽8768の2項目だけを確認する。
画面の更新で8項目を再取得し、写真・音楽の診断欄は別々に開閉できる。`RenderServerManagement`は4テーマ×7状態×2幅の56画面を合成値で検証する。本番反映・実クリックは別途確認する。
