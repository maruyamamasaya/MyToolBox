# 画像リサイズ

参照：[Web版](https://maruyamamasaya.github.io/tool/image-resizer/)。画像を選ぶ→寸法指定→プレビュー→別名保存の流れをmacOSネイティブで実装。SwiftUI＋ImageIO＋CoreGraphicsで完結し、Pythonや追加パッケージは不要。

## 操作

- ファイル選択で複数選択、または複数画像をwindowにドロップ（最大200枚）。新しい選択で入れ替え、同じパスの重複は除去。1枚の場合は従来のプレビュー・別名保存。
- 複数の場合は最初の読み込める画像をプレビュー。「一括リサイズして保存…」で保存先フォルダを指定すると、その中に新規フォルダを作って順番に変換・保存。キャンセルでは書き込まない。
- 一括時の倍率は各画像の元サイズに適用。ピクセル指定＋縦横比維持では最後に編集した幅または高さを全画像に適用し、反対側は各画像の比率で計算。維持OFFでは全画像を同じ幅×高さへ変形。
- 一括結果は保存済み／失敗を画像ごとに表示。失敗しても後続を継続。閉じると処理を中断するが、保存済みファイルは残る。保存先を開くボタンあり。
- 幅/高さを整数pxで指定。「縦横比を維持」は最後に編集した辺から反対側を四捨五入（最低1px）。ONへ戻すと幅を基準に補正。
- 25/50/75/100/200%は常に元画像を基準にする。
- PNGまたはJPEGを選択。元がJPEGなら初期値JPEG、それ以外はPNG。JPEG品質10〜100%、初期85%。
- 「リサイズする」でプレビュー・寸法・容量を表示。「画像を保存…」で保存先を選択。既定名は元名-幅x高さ.拡張子。
- 設定変更時は古い結果を消す。新しい画像の読込に失敗した場合も以前の画像/結果を残さない。

## 対応と上限

入力はJPEG/PNG/WebP/HEIC/HEIF/TIFF（OSのImageIOがデコードできるもの）、50MiB以下・4,000万画素以下。アニメーション/複数ページは拒否する。出力はJPEG/PNG、各辺1〜16,384pxかつ合計4,000万画素以内。Web版のWebP出力は実装せず、標準エンコーダーで安定して保存できる2形式に限定する。

高品質補間で拡大/縮小。縦横比OFFでは指定した縦横へ変形する。EXIFの向きを焼き込み、8bit sRGBで再描画。PNGは透明を保持、JPEGの透明部分は白背景。元のEXIF/GPS等のメタデータは転記しない。HDRや広色域の完全保持、容量の必ず縮小、拡大時の細部復元は保証しない。

入力を読取り、処理中はメモリで保持。一括処理は1枚ずつ読み込み・変換・保存し、全画像のピクセルを同時保持しない。明示保存だけ書込み、外部送信・自動保存なし。入力と同一パス・symlink・hardlinkへの保存を拒否する。1枚の別名保存で既存ファイルを置換する場合は標準保存パネルが確認する。一括保存は新規フォルダ＋連番付きファイル名と上書き禁止書込みを使い、同名画像も衝突しない。

## 検証

単体テストと合成画像による実ファイル往復・モデル動作・3テーマ描画を使用する。ファイルパネル/ドロップ等の実デスクトップ操作は自動描画と区別して記録する。

## 独立プロセス（次回デプロイ用）

画像リサイズを同梱helperとして起動する実装を追加。本体の終了・再起動では読込／変換／保存／一括処理を中断せず、画像選択・寸法／形式／品質・プレビュー・変換済みデータ・一括保存先と結果を画像側のモデルで保持する。再選択は起動済みの画面へ戻る。画像リサイズ自身を閉じる場合は従来どおり処理をキャンセルし、既に保存したファイルは残す。バックグラウンド検証と実機未確認の範囲は[記録](../sessions/2026-10-20-independent-image-git.md)。本番反映は別。

## 小窓・拡大切替

起動時は標準360×560pt（最小340×520pt）、拡大時1100×850pt（最小800×600pt）。小窓はプレビュー中心、拡大時は左にプレビュー・右にサイズ設定を配置する。入力画像・サイズ・形式・変換済みデータ・一括結果は同じモデルで保持する。元画像／変換後のプレビュー切替、幅・高さ・比率・形式、選択・リサイズ・保存を常設。倍率とJPEG品質・説明は歯車、一括結果と保存先を開く操作は結果popoverへ。既存の複数drop・一括保存・元画像保護は維持。本番反映は別途行う。
