# MyToolBoxのロードマップ

MyToolBoxはローカル完結のツール集。システムモニターはその1つとして維持する。メニューバーの数値表示は残し、別アイコンのツール一覧を共通の入口とする。

## 現在
ツール一覧とシステムモニターへの導線を実装。登録済みはモニター＋[初期5ツール](LOCAL_TOOLS.md)＋[テキスト3ツール](TEXT_TOOLS.md)＋[行/置換/リストの5機能](LINE_TOOLS.md)（営業日・音声・マイク・CSV閲覧/編集）。共通カードUI・色付きアイコン一覧と独立windowを実装。設定・ログイン起動・定期ログと既存モニター表示を維持。

## 次の段階
1. ツール一覧とモニターの実機操作・長時間安定性を確認。
2. 初期5ツールの実機受け入れ（音声・マイク、CSVファイル保存・再読込、休日UI）を行い、Undoやカレンダーの連続範囲表示等の差分を詰める。
3. ツールが増えた段階で検索・分類・お気に入りを検討。現時点では未実装。

追加候補（未決定・未実装）：タイマー、ストップウォッチ、スリープ防止、画像変換、一括リネーム、テキスト整形など。権限やファイル変更を伴う操作は個別に仕様と確認方法を決める。モニターの拡張案は[可視化ロードマップ](VISUALIZATION_ROADMAP.md)、移行判定は[実機チェックリスト](MIGRATION_CHECKLIST.md)で管理する。

## 設計方針
各ツールの処理を分離し、不要な常駐処理を増やさない。外部サーバー・有料APIに依存しない。ツールの数より実際に使う機能を優先する。

## 将来のWindows対応（開発メモ）
2026-10-15の方針：システムモニターは将来Windows版も開発できるように備える。当面はmacOS版を優先し、Windows版の実装・ビルド環境整備・大規模な構造変更は行わない。

- 今後モニターを変更する際は、値のモデル・差分計算・履歴などの共通処理と、OS固有の取得処理・UIとの境界を意識する。共通処理へのMac専用APIの追加を避け、必要になった段階で取得インターフェースの分離を検討する。
- Windows対応時はOS別の取得実装と画面・常駐部分を用意する。現在のMonitorKitはMac専用APIを含み、Windowsでビルドできることは確認していない。共通化の言語・UI技術・実装時期は未決定。
- CPU・GPU・RAM・通信・ストレージ・Battery・温度・ファンは、OSや機種ごとに取得可否と測定定義を確認する。全項目の同等対応を前提にせず、既存の取得不可・非搭載の状態表現を維持し、欠損を0や架空の値で補わない。
