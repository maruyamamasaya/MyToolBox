# 次段階の可視化

2026-10-15にユーザーが提示した4枚の参考画像に基づく要望整理。一覧カードと既存数値への詳細導線は小型ポップオーバーに実装済み。残る可視化案を以下に記載。

| 優先順 | 表示案 | 現在使える情報 | 追加取得・定義が必要な情報 |
| --- | --- | --- | --- |
| 1（実装済み） | CPU / GPU / RAM / SSD / Network / Batteryの一覧カード | 使用率、容量、送受信速度、残量、充電状態、CPU温度、既存60秒履歴 | SSDは空きと使用を明確に区別。現在の詳細画面へ行けるカード導線 |
| 2 | メモリ内訳の色分けバー | 総量、推定使用量、free、file-backed、圧縮、purgeable | wiredの公開、app memoryの計算定義、利用可能量の推定式。重複のない構成比にする。freeと利用可能を同一視しない |
| 3 | 温度・ファン詳細 | CPU全体/P/E/GPU平均、各センサー、2基の実回転数 | 今回は数値のみ。グラフを追加するなら5秒周期の履歴と値の取得時刻を保持 |
| 4 | IF別の当日送信／受信／合計表 | IF一覧と選択IFの速度、OSカウンター累積 | 複数IFの独立サンプリング、ローカル日次積算・永続化、日付境界・休止中の扱い。IF生成以降の既存累積を「本日」に流用しない |

通信表はIFごとの行を基本とし、VPN・bridge・物理IFの重複を含んだ合計は作らない。表示名は接続サービス名などを検討する。SSID取得は権限とプライバシーが別途関係するため、画像にあるSSIDが現在も取得できるとはしない。

当日通信量のreset/export、使用量の多いアプリ、メモリ解放ボタンは別機能。画像の見た目だけで取得方法や安全性を確定しない。特にメモリ解放は読み取り専用の監視と分けて仕様を検討する。

受け入れ条件：既存の数値と定義・単位が一致し、欠測は0のグラフにしない。非公開センサーの制約、推定メモリの扱い、通信量の集計期間を詳細画面から確認できること。
