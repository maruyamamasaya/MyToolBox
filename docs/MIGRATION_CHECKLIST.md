## ユーザー操作を含む試験

| 試験 | 再現手順 | 合否基準・記録 |
| --- | --- | --- |
| メニューバー・詳細 | OPERATIONSのopenで起動。CPU/GPU/RAM/通信の数値を確認しクリック。7カテゴリを選択 | 値と単位が読め、初回は計測待ち、取得不能は理由表示。閉じても常駐し終了ボタンで消える |
| 60秒グラフ | 70秒待ち、1→5→2秒に変更。CPU/GPU/RAM/Networkを確認 | 横軸が60秒、更新間隔で保持期間が縮まらない。受信／送信が識別可能。欠測時の0への偽落下なし |
| 設定保存 | 表示・順序・compact・単位・温度単位・IFを変更→終了→再起動 | 全設定が復元され、同じ順序でメニューバー表示。すべて非表示でもアイコンから詳細を開ける |
| CPU/GPU追従 | TESTINGの診断を実行。Parallelsと同じ時刻帯で観測 | 負荷区間で上昇、終了後低下。CPUは最大100%の全コア平均で比較。GPU内部平均窓は非公開なので瞬間完全一致を要求しない |
| 通信速度 | TESTINGのloopback、次にユーザーが通常の大容量LAN転送を行い該当IFを指定 | loopbackは受信／送信が共に増加。実IFは転送中に増加し、終了後に低下。自アプリは通信を発生させない |
| IF切替 | ユーザーがWi-Fi/EthernetまたはVPNを切り替える | autoの選択IFが変化、最初は計測待ち→2サンプル目から速度。異なる累積値の差で巨大スパイクを出さない。全IF down時は取得不可 |
| sleep/wake | ユーザーがMacを30秒以上スリープし復帰 | sleep中停止、復帰直後は差分待ち、2サンプル目で回復。sleep期間を転送時間に混ぜた偽速度がない |
| 時計変化 | 通常利用の時刻補正が起きた場合に確認（検証のため設定変更はしない） | 60秒保持は単調時刻、差分は非負。自動テストで時計逆行済み |
| 連続稼働 | 通常利用で8時間、可能なら24時間。Activity Monitorで10分ごとにCPU/RSS確認 | クラッシュ・停止なし。初期ウォームアップ後RSSに継続増加なし。暫定目標：非表示時平均CPU<2%（1コア100%基準）、RSS<200 MiB。表示時は別記録 |
| バッテリー | ユーザーが電源抜差し、放電状態を確認 | AC/充電状態が5秒周期程度で追従。残量はOS表示との差1ポイント程度。残時間は推定なしを許容し理由が正しい |
| ログイン起動 | 安定した配置先に.appを置き、ユーザーが設定の「有効にする」を押す。必要ならOSで承認し、ログアウト→ログイン | 状態と実際の起動が一致。重複起動なし。「無効にする」後は次回起動しない。Ad hoc署名での制約があればエラーを記録 |

ネットワーク設定変更・スリープ・電源操作・ログイン起動有効化はユーザー操作に委ねる。自動試験はこれらを勝手に実行しない。

## Parallels比較の記録方法（未実施）

両アプリのバージョン、時刻、更新周期、CPU負荷区間、選択IF、単位を揃えて最低60秒の平均・最小・最大を記録する。参考アプリの内部定義が不明な箇所は不明とする。

- CPU：MyToolBoxは全体最大100%、P/Eは各群の等重み平均。プロセス使用率や合計最大1000%と比較しない。
- GPU：ドライバー側の平均窓は不明。負荷区間の傾向を比較する。
- RAM：free/file-backed/purgeable/compressorの分類差を確認。使用量は推定なので差の原因を記録。
- Network：同一IFの同じ時間窓のbytes/s。bit/sなら8倍、KiB/sなら1024基準。累積の起算時点が違えば総量は一致しない。
- Storage：APFSコンテナ共有量とvolume単独量、purgeableを含む容量、仮想Diskを含むI/Oの差を整理。
- Battery：表示残量、OS健康状態、充放電条件を合わせる。容量維持率の推定値を校正済みとみなさない。
