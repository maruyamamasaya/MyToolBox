# 全カタログツールの独立プロセス化
Status: Accepted / Date: 2026-10-20

## Context
本体再起動時の作業継続を全55ツールで統一したい。起動していないツールまで常駐させる必要はない。

## Decision
ToolID.allCasesの全ツールを独立helperとして同梱し、選択時だけLaunchServicesで起動する。本体に画面モデルを持たせず、固有bundle IDで既存helperを再オープンする。通常の画面閉鎖は既存の終了確認・停止・cleanupを経てhelperを終了する。ウィンドウ配置のショートカットON時だけ、画面を閉じても常駐する。メモ／カレンダーのキーは既存の本体への所有移譲を維持する。

## Reason
本体からの寿命の分離と、一つのカタログ・ビルド・設定ドメインによる管理を両立する。Python梱包・検証もSwiftカタログから対象を読取り、手書きの対象リストのずれを防ぐ。

## Alternatives
残る単純な参照ツールを本体内に残す案は、利用者から見た再起動時の振る舞いが異なる。全helperを起動時に立ち上げる案は不要な資源を使う。

## Consequences
- システムモニターの独立画面は自身の取得・履歴を持ち、本体停止後も計測する。閉じたら終了する。本体のメニュー監視は従来どおり常駐するため、独立画面を開いている間は取得が2系統になる。
- 定期ログ・ログイン起動は本体だけが所有し、独立モニターは実行・登録しない。本体の管理設定入口は保持する。表示設定は既存ドメインで共有し、取得周期ごとに再読込する。
- 日程調整にも祝日を同梱し、ディレクトリツリーの保存先とAppStorageは既存ドメインを継続。マイクhelperは用途文とaudio-input entitlementを持つ。初回のOS許可は独立IDに対して利用者が判断する。
- 分離は編集中プロセスの保持であり、全ツールへの新しい自動保存は追加しない。ツール自体の終了時は既存仕様に従う。
- デプロイは別。検証ではOS起動・音声・マイク・AX・実キー・本番設定を操作しない。[作業記録](../sessions/2026-10-20-all-independent-tools.md)。
